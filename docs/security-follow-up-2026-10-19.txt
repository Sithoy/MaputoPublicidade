MP SECURITY FOLLOW-UP - 2026-10-19

Scope
Review of the user's 60 Snyk Code alerts (3 high, 25 medium, 32 low) in the

policies were changed during this follow-up.

Implemented
1. Auth proxy accepts only six explicitly mapped app endpoints and their permitted
   methods. Upstream paths come from constant strings, not free-form routing.
   Incoming query parameters are no longer forwarded: current app flows use JSON.
   Unexpected upstream redirects are rejected; Location is not forwarded. Requests
   have a 15-second upstream timeout. Existing login/signup/logout/refresh/session
   request shapes and supported config/session read methods are retained.
2. fetchWithAuth and fetchBlobWithAuth validate the destination BEFORE retrieving
   or attaching an MP token. Only root-relative, normalized /api/ paths are allowed.
   External origins, protocol-relative links, traversal escaping /api/, controls,
   backslashes and fragments are rejected. Redirect following is disabled even if
   a caller asks for it. Transient errors do not clear the session.
   This closes a potential token-exfiltration boundary if untrusted API-provided
   URLs reach these helpers; no observed production exploitation is claimed.
3. Zoho OAuth navigation reconstructs its destination from a fixed HTTPS endpoint.
   Exact origin/path validation is retained; userinfo, fragments and malformed
   values are rejected. Opaque OAuth query values are preserved.
4. New signing-boundary tests demonstrate that knowledge of either public SALT
   value is insufficient to forge customer tokens: wrong keys, wrong namespaces
   and tampering fail verification. Existing expiry/revocation tests also pass.
   Signing namespaces and the production SECRET_KEY were NOT changed, preserving
   existing customer tracking and artwork links.
